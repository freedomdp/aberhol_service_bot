# Протестированные подходы к обработке callback queries в Telegram боте

## ❌ НЕ РАБОТАЮЩИЕ ПОДХОДЫ

### 1. Вынесение callback handlers из ConversationHandler с высоким приоритетом (group=-1)
**Дата тестирования:** 2025-12-11  
**Проблема:** Callback queries не доходят до обработчиков вообще. В логах нет ни одного `[UPDATE DEBUG] CALLBACK QUERY` сообщения, даже при множественных нажатиях на кнопки.  
**Вывод:** Подход не работает в принципе. Callback queries либо не отправляются Telegram, либо блокируются на уровне библиотеки до обработчиков.  
**Статус:** ❌ НЕ РАБОТАЕТ

---

## ✅ РАБОТАЮЩИЕ ПОДХОДЫ

### 1. Использование ReplyKeyboard вместо InlineKeyboard для выбора наличия номера заказа
**Дата тестирования:** 2025-12-11  
**Описание:** Замена InlineKeyboardMarkup на ReplyKeyboardMarkup для кнопок выбора наличия номера заказа. Reply кнопки обрабатываются как обычные текстовые сообщения через MessageHandler с фильтром по тексту кнопки.  
**Реализация:**
- Создана функция `get_order_choice_keyboard()` в `src/keyboards/reply.py`
- Обработчики `handle_order_yes` и `handle_order_no` переписаны для работы с обычными сообщениями
- ConversationHandler настроен для обработки reply кнопок в состоянии `BD_WAITING_ORDER`
- Убраны callback handlers для `order_yes`/`order_no` из `main.py`  
**Результат:** ✅ РАБОТАЕТ! Reply кнопки успешно обрабатываются, пользователь может выбрать вариант и диалог продолжается.  
**Статус:** ✅ РАБОТАЕТ
